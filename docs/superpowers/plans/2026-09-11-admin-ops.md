# Admin ops Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** The operator console's Ops tab — health, recorded and locked job runs with Run now, and a backup list with an audited download.

**Architecture:** A `job_run` table and a per-job advisory lock inside a new `cron.Start`/`cron.Run` that every caller (scheduler, CLI, console) goes through. Three strict-server admin operations plus one hand-routed download behind a new `sysadminChain`. One new console screen and a status line on Overview.

**Tech Stack:** Go (net/http, oapi-codegen strict server, pgx, sqlc, goose), React + TanStack Query, Playwright.

**Spec:** `docs/superpowers/specs/2026-09-11-admin-ops-design.md`

## Global Constraints

- Spec first: edit `openapi/pjokk.yaml`, then `go generate ./...` in `apps/server`; `sqlc generate` separately; `bun run gen:client` for the SPA types.
- Every admin write audits first, checked (`audit(ctx, q, admin, action, target, detail)`).
- Stale thresholds: nightly 26 h, frequent 30 min. Console run timeouts: nightly 1 h, frequent 10 min. `job_run` retention 30 days. Last 10 runs per job.
- Error text truncated to 500 characters.
- No credential ever in a response body.
- Green gate before the PR: `bun run check`, `goreleaser check`, `bun run test`, `golangci-lint run`, `go test -p 1 -count=1 ./...`, full Playwright with `--workers=2`.
